# Computer: карточки действий на компьютере пользователя

Создано: 2026-11-06. Код: `Partnerly/Computer` (сайт) и `Partnerly.Agent` (программа для ПК).

## Зачем и как устроено

Сайт на сервере не может сам управлять ПК пользователя (браузер этого не позволяет). Поэтому есть небольшая программа **Partnerly Agent** (Windows, значок в трее). Она сама подключается к сайту и выполняет команды карточек.

```
карточка агента ──> ComputerGateway ──SignalR /computerHub──> Partnerly.Agent на ПК ──> файлы / программы / экран
                         ^                                           |
                         └──────────── ответ (Result) ───────────────┘   события ПК (Event) ──> триггеры
```

- Подключение ПК — это обычное **подключение интеграции** (`AutomationConnection`, вид `computer`), как Telegram или Google. **Новой таблицы и миграции нет.** Хэш токена лежит в зашифрованном payload подключения.
- Карточка выбирает подключение «Компьютер» в окне свойств; чужое подключение выбрать нельзя (та же проверка владельца, что у интеграций).
- Хаб `/computerHub` без cookie сайта: программа доказывает себя токеном `pc.<id подключения>.<секрет>`. В базе хранится только SHA-256 секрета. Токен показывается один раз; кнопка «Новый токен» отключает старую программу.
- Один ПК = одно подключение; если с тем же токеном подключится вторая копия, первая получает `Replaced` и останавливается.

## Что умеют карточки

36 действий и 12 триггеров (коды в `ComputerTypeCodes`; строки «Новое» добавлены 2026-11-06 второй волной):

| Группа | Карточки |
|--------|----------|
| Экран | уведомление, окно с сообщением (OK или Да/Нет), озвучить текст, скриншот |
| Открыть, буфер | открыть ссылку / файл / папку, скопировать в буфер, прочитать буфер |
| Информация | сведения о ПК (диски, память, батарея), запущена ли программа |
| Файлы | прочитать / записать текстовый файл, список папки, копировать, переместить, ZIP, сохранить вложение на ПК, взять файл с ПК (становится вложением Partnerly) |
| Программы | запустить программу, запустить скрипт (.ps1 / .bat / .cmd), закрыть программу (вежливо) |
| ПК | заблокировать, сон |
| Новое: файлы | создать папку, файл в Корзину (только файлы, можно вернуть), проверить файл, распаковать zip, скачать файл по ссылке (до 100 МБ; программы и скрипты не скачиваются) |
| Новое: ПК и звук | экран выкл., громкость, кнопки музыки (клавиши Windows), выключить / перезагрузить / выйти (15–600 с, по умолчанию спрашивает владельца), отмена выключения |
| Новое: информация | окно на переднем плане, открытые программы, сеть (IP), ping (команда `ping_host`; команда `ping` — проверка связи с сайтом) |
| Триггеры | новый файл в папке, ПК вышел в сеть / отключился, на ПК запущена программа |
| Новое: триггеры | файл изменён, файл удалён, программа закрыта, блокировка / разблокировка / сон / пробуждение / вход и выход Windows, текст в буфере (по умолчанию выключено), зарядка и батарея (20 / 10 / 5 %), USB-диск, никого за ПК и возвращение, мало места на диске |

Файлы до 8 МБ передаются в base64 (лимит сообщения хаба поднят до 14 МБ в `Program.cs`). `get_file` и `screenshot` кладут результат во вложение Partnerly (`IAttachmentService.UploadAsync`, сущность `AutomationRun`), поэтому следующие карточки (Telegram, Drive) берут `{{steps.<имя>.result.attachmentId}}`. Допустимые расширения проверяет обычная настройка вложений сайта.

## Безопасность (что решено)

Запросы сайта **не доверенные**: всё проверяется на ПК по файлу настроек. Чего нет в списках, отклоняется.

- `allowedFolders` — только эти папки (и всё под ними) для чтения / записи / копирования / ZIP / открытия. `PathGuard` отклоняет `..`, относительные пути, `\\?\`, альтернативные потоки данных (`:`), ссылки и junction внутри папки. Совпадение по имени-приставке (`Docs` и `Docs-evil`) не проходит.
- `allowedPrograms` — запуск и закрытие только программ из списка, имя совпадает дословно. Программы запускаются без оболочки (`UseShellExecute=false`). Закрытие — только `CloseMainWindow`, процессы не убиваются (кроме процесса, запущенного самой карточкой при превышении времени).
- `scriptFolders` — скрипты только из этих папок, только `.ps1` / `.bat` / `.cmd`.
- Карточка «Открыть» не запускает программы и скрипты (список расширений); для них есть «Запустить программу».
- `confirmOps` — команды, которые сначала спрашивают клик на ПК (`run_program`, `run_script`, `close_program`, `lock`, `sleep` и т.д.).
- `watchFolders` / `watchPrograms` — что ПК вообще сообщает сайту; лимит 120 событий в минуту на ПК.
- Тест-запуск карточки (dry-run) не выполняет действия с побочным эффектом; чтение выполняется.
- **Сознательно не сделано:** произвольная команда оболочки, эмуляция клавиатуры и мыши, реестр, удаление файлов.
- Текст озвучки передаётся программе через стандартный ввод, а не в командной строке.

## Настройки программы (упрощены в 1.5.0, 2026-11-07)

Файл `%AppData%/PartnerlyAgent/config.json` (создаётся при первом запуске; меню в трее → «Settings...», править файл вручную не нужно). Папку можно переопределить переменной `PARTNERLY_AGENT_HOME`. Лог — `agent.log` рядом (токен в лог не пишется).

В окне три вкладки:

- **Folders** — папки, которым доверяет владелец ПК. Внутри них (и во всех вложенных) Partnerly может читать, писать, копировать, архивировать, **наблюдать за файлами**, **запускать скрипты** (.ps1 / .bat / .cmd) и **работать с Git** в любых найденных репозиториях. Отдельных списков для скриптов, наблюдения и репозиториев больше нет (старый файл при чтении сливается в этот список один раз, `SettingsVersion = 2`).
- **Programs** — программы, которые можно запускать, закрывать и за запуском / остановкой которых следить.
- **Safety** — «спросить меня сначала» (список команд, включая Git push и опасные команды Git), три необязательных оповещения: копирование текста, «никого нет за ПК», мало места на диске.

```json
{
  "server": "https://сайт",
  "token": "pc....",
  "allowedFolders": ["C:/Users/me/Documents/Partnerly", "C:/Dev"],
  "allowedPrograms": ["notepad.exe"],
  "confirmOps": ["shutdown", "delete_file", "run_script"],
  "enabled": true,
  "watchClipboard": false,
  "idleMinutes": 10,
  "diskLowGb": 5,
  "gitHosts": [],
  "gitPath": "",
  "gitRunHooks": false,
  "gitAskForRisky": true,
  "gitPushWithoutAsking": false,
  "settingsVersion": 2
}
```

Тонкие настройки Git (`gitHosts` — ограничить хосты адресов, пусто = любой хост по https / ssh / git; `gitPath`; `gitRunHooks`) есть только в файле. Пути можно писать с `/` и переменными окружения. После сохранения программа перезапускается сама.

**Сайт видит всё внутри разрешённых папок.** В редакторе у поля с путём кнопка «Browse…» открывает список: сначала разрешённые папки, затем содержимое (папки, файлы, значок у репозиториев Git); файл или «Use this folder» подставляется в поле. Это команда агента `browse` (`Security/FolderBrowser.cs`), всё через `PathGuard`; ссылки, скрытые и системные файлы не показываются, до 300 записей на папку. Кнопка «Choose…» (окно Windows на ПК) осталась.

**Наблюдение** (триггеры файлов, программ, репозиториев) теперь работает по всем разрешённым папкам и программам. Шум отбрасывается на ПК: `.git`, `node_modules`, `bin`, `obj`, кэши, `~$*`, `*.tmp`, `*.crdownload`, `desktop.ini`. Репозитории для триггеров Git находятся сами (до 3 уровней вглубь, не больше 30; по 6 за круг раз в 15 с).

**Скрипты и защита.** Раз скрипт можно запускать из любой разрешённой папки, программа не пишет туда программы и скрипты (`write_file`, `save_file`, `copy_file`, `move_file` отклоняют .exe, .bat, .cmd, .ps1, .vbs и т.п.); новый файл настроек по умолчанию спрашивает перед `run_script`, а старый без отдельных папок скриптов получает этот вопрос при слиянии.

## Скачивание и установка (с 2026-11-06)

1. Администратор один раз собирает программу: `powershell -File tools/publish-agent.ps1`. Получается один самодостаточный файл `Partnerly.Agent.exe` (около 66 МБ, .NET уже внутри, на ПК ничего ставить не нужно, нужна Windows 10 или новее) в `Partnerly/App_Data/agent` (в Git не попадает; другая папка — настройка `Agent:DownloadFolder`). Пока файла нет, на странице «Интеграции» вместо кнопки скачивания показывается подсказка.
2. Пользователь на `/Integrations` в карточке «Компьютер» нажимает «Добавить» → «Создать». В окне с токеном кнопка «Скачать программу с этими настройками» отдаёт `Partnerly-Agent.zip` (`DownloadAgentWithSettings`): `Partnerly.Agent.exe` + `config.json` с адресом сайта и токеном + `README.txt`. Токен сайт не хранит, поэтому он проверяется по хэшу перед упаковкой (чужой или неверный токен → 404). Кнопка «Скачать только программу» (`DownloadAgent`) отдаёт zip без настроек.
3. Пользователь распаковывает и запускает `Partnerly.Agent.exe`. Программа: проверяет Windows 10+ (иначе сообщение), забирает `config.json` рядом с собой в `%AppData%/PartnerlyAgent` (папки по умолчанию: `Documents/Partnerly`) и удаляет лишний файл с токеном, предлагает установку для текущего пользователя (копия в `%LocalAppData%/Programs/PartnerlyAgent`, автозапуск с Windows, права администратора не нужны) и запускает установленную копию. Если «Нет» — работает с того места, где лежит.
4. Если настроек в zip нет (скачана «только программа»), при первом запуске откроется окно для адреса сайта и токена.

Установщика MSI, подписи кода (при первом запуске SmartScreen может предупредить «неизвестный издатель») и удаления из меню нет (см. KNOWN_ISSUES KI-019): чтобы удалить, выключите «Start with Windows», закройте программу и удалите папку установки и `%AppData%/PartnerlyAgent`. В трее: статус подключения, файл настроек, лог, «Start with Windows» (запись в `HKCU/.../Run`, снимается тем же пунктом), выход.

## Подключение и протокол

Клиент: `Microsoft.AspNetCore.SignalR.Client` 6.0.36 (единственный новый пакет; на сайте новых пакетов нет). Токен идёт в `access_token`.

| Сторона | Метод | Смысл |
|---------|-------|-------|
| агент → сайт | `Hello(machine, os, version)` | один раз после подключения, сайт показывает на карточке |
| сайт → агент | `Execute(commandId, op, argsJson)` | команда |
| агент → сайт | `Result(commandId, ok, dataJson, error)` | ответ; принимается только от ПК, которому послана команда |
| агент → сайт | `Event(type, payloadJson)` | `file_created`, `program_started` (до 8 КБ) |
| сайт → агент | `Replaced` | подключилась другая копия |

`computer.status_changed` сайт создаёт сам при подключении и отключении хаба. Если ПК не в сети, карточка завершается ошибкой «The computer is offline…» (повторяемой); путь ошибки агента работает как обычно. События, случившиеся пока ПК был не в сети, не накапливаются.

## Программа на ПК: версия 1.2.0 (2026-11-06)

- **Значок и состояние.** Значок `Assets/app.ico` (создаётся `tools/make-agent-icon.ps1`, файл лежит в репозитории); в трее на нём цветная точка: зелёная — подключено, жёлтая — подключение, серая — нет связи или пауза, красная — проблема (токен отклонён, другая копия заняла компьютер).
- **Включение и выключение.** Пункт меню «Let Partnerly use this computer» (`enabled`): выкл. — программа отправляет сайту `Goodbye("paused")`, отключается и останавливает наблюдателей; на сайте карточка «Приостановлено на ПК». Вкл. подключает заново без перезапуска.
- **Установка без ошибок.** Запуск прямо из zip (рядом нет `config.json`) определяется, программа объясняет «сначала распакуйте»; повторный запуск говорит «уже работает, ищите значок у часов»; после первого подключения окно «Готово» (где значок, что разрешено); если связи нет 30 секунд, показывается подсказка с причиной; «Check connection» идёт по шагам (настройки, DNS, порт, это сайт Partnerly). Окно «Добавить компьютер» на сайте ведёт по 4 шагам и само зеленеет, когда программа подключилась (опрос `ComputerStatus` каждые 2 с).
- **Удаление и сбои.** Пункт «Remove program...» и запись в «Параметры Windows > Приложения» (`--uninstall`, раздел реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\PartnerlyAgent`; при каждом запуске установленной копии запись и автозапуск проверяются и чинятся). Удаляются автозапуск, запись в «Приложения», по желанию настройки и журнал; папка установки удаляется отдельным скрытым процессом после выхода; сайт получает `Goodbye("uninstalled")` («Программа удалена»). Если файл удалён руками, карточка остаётся «не в сети» с подсказкой «Почему не в сети?» (6 причин). Файл настроек пишется через временный файл с копией `.bak` и восстанавливается при повреждении; необработанные ошибки пишутся в журнал; после смены настроек или токена программа перезапускается сама (`--restart`, ждёт закрытия старой копии до 20 с).
- **Какие папки доступны, видно в редакторе.** После подключения программа присылает сайту списки разрешённых папок, программ и скриптов (метод хаба `Settings`, без токена; хранится в payload подключения как `settings`); поля путей в карточках — выпадающий список с возможностью вписать своё. Это подсказка: решение на запуске всё равно принимает ПК.
- **Наблюдатели** (`Net/Watchers.cs`): один цикл раз в 3 с (программы, буфер, диски, простой, батарея), `FileSystemWatcher` для папок (раз в 30 с подхватываются появившиеся позже папки и пересоздаются упавшие), `SystemEvents` для блокировки и сна. Лимит событий 120 в минуту на компьютер сохраняется.
- **Правило для новых команд ПК** (уточнение TR-2026-11-06-04): `case` в `CommandRunner` + класс в `ComputerActions.cs` + регистрация в `ComputerModule` и `ComputerServiceCollectionExtensions` + форма в `builder-forms-computer.js` + иконка и переменные в `builder.js` + ключи `NodeTypeComputer…` и `BuilderIntPc…Intro` в трёх resx и в `_BuilderI18n.cshtml`.

## Git на ПК (версия 1.4.0, 2026-11-07)

Одна команда агента `git` (`Commands/GitRunner.cs`, `Security/GitGuard.cs`), на сайте 15 карточек (`ComputerGitActions.cs`: status, log, diff, branches, fetch, pull, commit, push, switch, clone, init, merge, tag, stash и универсальная **Git command**) и 2 триггера (`computer.git_new_commit`, `computer.git_changed`). Решение и причины: TR-2026-11-07-01.

- **Настройки:** отдельной вкладки нет. Git работает в репозиториях внутри разрешённых папок (Folders). Вопросы перед push и опасными командами — вкладка Safety. Файл: `gitHosts` (пусто = любой хост), `gitPath`, `gitRunHooks` (выкл.), `gitAskForRisky` (вкл.), `gitPushWithoutAsking` (выкл.).
- **Разрешено:** status, log, diff, show, rev-parse, describe, shortlog, blame, ls-files, ls-tree, ls-remote, rev-list, merge-base, name-rev, grep, count-objects, var; add, commit, fetch, pull, push, switch, checkout, merge, stash, tag, branch, restore, reset, rebase, clean, cherry-pick, revert, rm, mv, remote, init, clone.
- **Не разрешено:** config, submodule, gc, credential, apply, am, difftool, mergetool, bisect, archive, filter-branch и всё, чего нет в списке выше. Опции, запускающие программы или читающие файлы вне репозитория (`-c` у clone, `--upload-pack`, `--exec`, `-x`, `--ext-diff`, `--no-index`, `--output`, `-F`, `--contents`, `--recurse-submodules` и их сокращения), отклоняются. Адреса — только https / ssh / git на разрешённых хостах; локальные пути, `file://`, `ext::` не принимаются.
- **Спрашивает клик на ПК:** любой `push`, `remote add / set-url`, рискованные команды (`push --force`, `reset --hard`, `clean`, `rebase`, `restore` без `--staged`, `branch -D`, `stash drop`, `commit --amend`, `rm` без `--cached`…), команды из «Ask me first» (`git`, `git_<команда>`).
- **Вход:** используются учётные данные самого ПК (Git Credential Manager, SSH). Интерактивный вход отключён (`GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`).
- **Результат:** `command`, `repo`, `exitCode`, `output`, `errorOutput`, `text`; ненулевой код — ошибка карточки. `commit` с «что добавить» делает `git add` и `git commit`, возвращает `committed`, `sha`, `subject` («нечего коммитить» — не ошибка).
- **Триггеры:** раз в 15 с по найденным репозиториям (по 6 за круг) (`rev-parse HEAD`, `branch --show-current`, `status --porcelain`): новый коммит на той же ветке (смена ветки — не новый коммит) и переход «есть изменения» ↔ «чисто». Первый просмотр только запоминает состояние.
- **Тесты:** `AgentGitTests.cs` (GitGuard и настоящий git во временной папке), `ComputerGitCardTests.cs`.
