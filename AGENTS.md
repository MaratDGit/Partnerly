## Назначение

Partnerly — монолитное веб-приложение ASP.NET Core MVC на **.NET 6**: пользователи, роли, права, группы, уведомления, обращения в поддержку, вложения, шаблоны писем, системные настройки, журнал. Отдельных class-library проектов в решении нет (`Partnerly.sln` → `Partnerly/Partnerly.csproj`).

## Архитектурные принципы (подтверждено кодом)

- Слои внутри одного проекта: Controllers → Services → Repositories → `AppDbContext`.
- Интерфейсы: `Infrastructure/Interfaces`. Реализации: `Infrastructure/Services`, `Infrastructure/Repositories`.
- Большинство админских экранов наследуют `_BaseController` с `[Authorize]`. `AccountController`, `HomeController`, `AIController`, `LanguageController`, `SearchController`, `AutomationHooksController` (анонимный входящий webhook с HMAC) — отдельные контроллеры.
- Списки — собственная система DataTable (регистрация опций в ViewModel, запросы через `DataTableQueryService`). Это не SPA.
- Права: политики `Permission:{code}` → `PermissionPolicyProvider` + `PermissionAuthorizationHandler` + `IPermissionService`. Политики стоят на CRUD/Data/Export основных модулей и на `AutomationController` (`automation.*`). Видимость записей — `IUserVisibilityService`. Старый `HasPermision` удалён (2026-10-25).
- События: внутрипроцессный `IEventBus` / `EventBus`; `AutomationEventBridge` подписан на те же события и запускает автоматизации.
- Модуль Automation (меню «Agents»): код в `Partnerly/Automation` (свой `AutomationController` в `Automation/Web`), hosted `AutomationWorker`, хаб `/automationHub`, редактор Drawflow на `/Automation/Builder/{id}`. Подробности: `docs/ai/Automation/ARCHITECTURE.md`.
- Интеграции (Telegram, Google Sheets / Gmail / Drive, WhatsApp): `Partnerly/Integrations`, подключаются к Automation через `IAutomationModule`, страница `/Integrations`. Новые внешние сервисы добавлять туда же по тому же образцу. Подробности: `docs/ai/Integrations/INTEGRATIONS-PLAN.md`.
- Компьютер пользователя (`Partnerly/Computer`, программа `Partnerly.Agent` для Windows): подключение вида `computer` (без своей таблицы), хаб `/computerHub` по токену, карточки `computer.*`. Подробности: `docs/ai/Computer/COMPUTER-AGENT.md`.
- UI: Razor, layout по умолчанию `_ContentNavbarLayout`, локализация `en` / `ru` / `hy`.
- Платежи (`Payment`) и транзакции (`Transaction`) есть в модели, контроллеров под них нет.

Подробности: `docs/ai/Architecture.md`, `docs/ai/DEVELOPMENT_STANDARDS.md`.

## База данных

- Изучай схему через сущности, `AppDbContext`, Fluent API и миграции в `Partnerly/Migrations`.
- Доступ к папке проекта **не** даёт права менять БД.
- **Запрещено без явного разрешения владельца:** подключение к производственной БД, изменение данных, запуск миграций, изменение схемы, удаление таблиц/записей/столбцов, необратимые SQL-операции.
- `DbInitializer.Initialize` вызывает `EnsureCreated()` при старте — существующее поведение; не усиливай его и не запускай миграции «заодно».
- Строки подключения и учётные данные БД не копировать в документы.

Подробности: `docs/ai/DATABASE.md`.

## Секреты и безопасность

- Живые ключи: `dotnet user-secrets` и локальный `Partnerly/secrets.json` (в `.gitignore`).
- В `appsettings.json` для Google / Apple OAuth, `EmailSettings:Password` и `SeedUser:Password` оставляй пустые плейсхолдеры. Живые значения — в `secrets.json` / user-secrets.
- Не коммить `secrets.json`, `.env`, ключи API, пароли seed-пользователя.
- Пароль seed-пользователя читается из `SeedUser:Password`, в коде его нет. Email и имя seed-пользователя — в `Constants`, не дублируй их в документации.

## Сборка и проверка

```text
dotnet build "Partnerly.sln"
```

С 2026-11-02: `dotnet test "Partnerly.Automation.Tests/Partnerly.Automation.Tests.csproj"`. Остальной монолит без тестов.

Если у владельца запущено приложение, `Partnerly.exe` в `bin` заблокирован и сборка падает на копировании (MSB3027). Не останавливай его процесс — собирай во временную папку: `-p:OutDir=<временная папка>\` (без переноса `obj`).

## Правила экономного использования контекста и токенов

1. Не анализируй весь проект повторно для каждой задачи.
2. Перед началом задачи прочитай краткий обзор проекта и актуальный документ продолжения работы.
3. Изучай только файлы, непосредственно связанные с задачей, и их реальные зависимости.
4. Не читай большие файлы полностью, если достаточно конкретного метода, класса или участка.
5. Не выводи повторно содержимое файлов, которое уже доступно в текущем контексте и не изменилось.
6. Не создавай несколько документов с одинаковой информацией.
7. Поддерживай краткий обзор проекта и краткое состояние текущей работы. Подробности храни в специализированных документах.
8. Не записывай в журнал полный текст запросов, длинные фрагменты кода или пошаговые внутренние рассуждения. Фиксируй цель, результат, изменённые файлы, проверки и важные решения.
9. Не запускай повторно сборку и тесты без причины, если соответствующие изменения не затрагивают проверяемую область. При этом не пропускай необходимые проверки.
10. Не выполняй широкие поиски по всему репозиторию, если известны нужные файлы или символы.
11. Не запускай параллельно несколько агентов для одной небольшой задачи.
12. Не используй расширенный режим контекста без реальной необходимости.
13. Для небольших исправлений предпочитай минимальные изменения и краткие ответы.
14. Перед большой задачей сначала составь компактный план и определи область изменений.
15. Если контекста недостаточно, прочитай только недостающие документы или участки кода.
16. После завершения задачи обновляй документацию только в тех местах, где действительно изменились знания о проекте.
17. Не жертвуй корректностью, безопасностью и необходимыми тестами ради экономии токенов.
